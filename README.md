# movie_editor（ローカル MVP）

ブラウザ上で動くマルチトラック動画エディタです。素材のアップロード、タイムライン編集（分割・結合・Undo/Redo）、Canvas 合成プレビュー、ffmpeg による書き出しまでを単一の Next.js プロセスで行います。

[`scripts/restore_speed.sh`](scripts/restore_speed.sh) と同等の ffmpeg フィルタで「倍速っぽい動画」を元の速度・音程へ戻す機能も含みます。

## 主な機能

### 素材・タイムライン

- **素材ライブラリ** — 動画（mp4/mkv/avi/mov/flv/wmv）と画像（png/jpg/jpeg/webp/gif）を複数同時アップロード
- **マルチトラックタイムライン** — 素材をドラッグして配置、トラック追加（+）、移動・端ドラッグで長さ変更
- **クリップ編集** — 分割・結合（同一トラック・複数選択）・削除・複製
- **重なり回避** — クリップ移動時、同一トラック上の重なりを自動で前後にスナップ
- **フィルムストリップ** — 動画クリップにサムネイル帯を表示（アップロード後に非同期生成）
- **タイムラインズーム** — 0.25×〜4×

### プレビュー・合成

- **Canvas プレビュー** — 複数トラックの映像を重ね合わせ（下位トラックが背面）
- **変形** — 選択クリップの移動・四隅ハンドルでスケール、ダブルクリックまたは ⛶ で画面フィット
- **再生** — 再生/一時停止、1フレーム送り、先頭/末尾ジャンプ、全画面プレビュー
- **音声** — 最上位の動画トラックの音声をプレビュー再生（書き出しも同トラック基準）
- **レイアウト** — プレビューとタイムラインの境界をドラッグで高さ調整（`localStorage` に保存）

### ジョブ・書き出し

- **速度復元** — 選択した動画クリップに `scripts/restore_speed.sh` 相当の ffmpeg 処理を適用
- **選択クリップ書き出し** — タイムライン上の区間を mp4 でダウンロード
- **全体書き出し** — 「合成解像度」で設定したサイズのタイムライン合成を mp4 でエクスポート
- **合成解像度** — 1920×1080（16:9）・1080×1920（9:16）・1080×1080（1:1）のプリセット、最初のクリップ配置時の自動設定、選択クリップの「素材に合わせる」に対応
- **Undo / Redo** — 編集操作の取り消し（Ctrl+Z / Shift+Ctrl+Z）

### プロジェクト保存・読み込み（ローカルストレージ）

- 「新しい保存版を保存」で、素材一覧・トラック・配置・切り出し／結合 parts・変形・合成サイズ／時間・名前をサーバーへ明示保存します。空プロジェクト・素材だけの状態も保存できます。
- 保存は毎回独立した版になります。保存一覧から読み込み、同じ内容の JSON ダウンロード、保存版の明示削除ができます。ダウンロード開始はサーバー保存の成否・ダウンロード完了と区別して表示します。
- 保存版が参照する素材は「編集終了・素材解放」後も残ります。保存版を削除するとその版の保護だけを解除します。他版・他タブ・実行中ジョブの参照は維持します。保存版は最大50件で、上限では自動削除せずエラーにします。
- JSON は `format: "movie-editor-project"` の専用 DTO です。縦横比保持を含む保存は version 2、すべて引き伸ばしの保存は version 1 となります。両方を読み込めますが、未知の version は拒否します。素材本体、URL、絶対パス、Undo/Redo、再生位置、選択、ジョブ実行状態は含みません。JSON は最大2 MiB、素材50件、トラック20件、クリップ100件、各クリップの parts 50件、合成時間24時間までです。
- 読み込みは形式・参照・数値範囲・素材の実ファイル SHA-256／サイズ・実動画区間をすべて検証し、タブの素材保護を永続化してから一括採用します。停止・位置0・選択なし・新しい履歴で開始します。未保存変更には保存／破棄／キャンセルを確認し、失敗・欠損・キャンセルでは既存の編集と履歴を維持します。
- 欠損素材は同じバイト列のファイルを再指定してください。同名だけでは対応付けません。速度復元済み素材には元動画ではなく復元後の成果物が必要です。素材の論理IDは再指定後も維持し、保存先IDと区別します。
- 素材保護と保存版 manifest は `storage/retention.json` 内に同居し、同じ排他処理と原子的なファイル置換で確定します。応答消失時の再試行も同じ保存版IDで処理し、旧保存版の上書き・保護解除を行いません。削除済み保存版IDは素材参照を持たない削除記録として残し、遅延した保存再試行による復活を拒否します。ジョブ成果物を参照する場合は、再起動後の解決に必要なジョブ情報も原子的に永続化してから成功を返します。単一 Next.js プロセス専用です。Blob を使用する構成では保存・読み込みを明示拒否します。
- バックアップ・移動時には JSON と対応する素材ストレージを別途保管してください。素材を含まない JSON だけでは別環境での再開を保証しません。

## 使い方（概要）

1. ブラウザで `http://127.0.0.1:3000` を開く
2. 左の素材パネルから動画・画像をアップロード
3. 素材カードをタイムラインのトラックへドラッグするか、カードの「Tnの再生位置へ追加」でクリップを配置
4. 中央の Canvas プレビューで位置・サイズを調整、下部ツールバーで分割・結合・書き出しなどを実行

追加ボタンは Tab で選び、Enter／Space でも操作できます。追加先は選択中クリップのトラック（複数選択時は最初に選択した有効なクリップ）で、選択がなければ最上段のトラックです。ボタンの T 番号で確認できます。トラックがなければ「＋」で追加してください。

追加する区間が既存クリップと重なる場合は空き位置へ調整し、素材パネルに実際の追加先と秒数を表示します。他のクリップは動かしません。追加は初回の合成解像度設定も含めて1回の Undo で戻せます。

### 合成解像度の設定

- 空プロジェクトの初期値は 1920×1080 です。空のタイムラインへ最初の動画・画像クリップを配置すると、素材の寸法が取得できていれば合成解像度を自動設定します。全クリップを削除してから配置し直した場合も同じです。アップロードだけでは変更せず、すでにクリップがあるタイムラインへの追加でも変更しません。
- プレビュー上部の「合成解像度」から 16:9・9:16・1:1 のプリセットを選べます。空のタイムラインで選んだ設定は初回配置時の自動設定で変わるため、プリセットで書き出す場合は配置後に選んでください。
- クリップを選んで「素材に合わせる」を押すと、その素材から合成解像度を再設定します。複数選択時は選択一覧の先頭クリップ、結合クリップでは先頭パートの素材を基準にします。
- 素材からの自動／手動設定は元のピクセル数をそのまま採用するのではなく、長辺を1920ピクセルに換算し、各辺を320〜4096ピクセルの範囲の偶数へ調整します。たとえば3840×2160は1920×1080、正方形は1920×1920になります。プリセット以外のサイズは「カスタム」と表示されますが、幅・高さの任意入力はありません。
- 新しくアップロードした動画は、認識できる表示行列の90度単位の回転を素材寸法へ反映し、初回配置時の自動合成解像度に使います。既存の保存版の素材寸法・合成解像度・クリップ配置は変更しません。任意角度、SAR、画像のEXIF回転、旧APIの寸法や既存素材の「素材に合わせる」の再解釈は対象外です。
- 合成解像度はプレビューの縦横比と全体書き出しに反映されます。既定では各クリップを変形領域へ引き伸ばして描画します。明示的に「縦横比を保持（全体を表示）」を選ぶと、素材全体を枠内中央に収め、余白は透明になります。詳しくは「クリップの縦横比を保持する」を参照してください。選択クリップ書き出しは別の処理で、詳細は末尾の仕様を参照してください。

設定を手動確認する場合は、合成した横長・縦長・正方形の動画／画像を使い、空のタイムラインへの初回配置、2本目の追加、プリセット切替、「素材に合わせる」を順に確認します。全体書き出し後は `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of json output.mp4` で、出力寸法が画面の合成解像度と一致することを確認してください。既存データを使わず、専用の一時ストレージで検証してください。

## 素材保護と結合クリップの仕様

- タブごとに素材保護セッションを作り、`storage/retention.json` に保護IDを原子的に記録します。素材一覧・タイムライン・Undo/Redoの全履歴・復元ジョブ成果を含み、保護情報は追加方式です。アップロードは同一バッチの全IDを保存前にまとめて予約し、別タブの参照はそのタブが解放するまで残します。
- **「編集終了・素材解放」** で、このタブの編集内容・素材一覧・履歴を破棄することを確認すると参照を解放します。他タブも実行中ジョブも参照しなくなった管理対象だけを自動整理します。通常のタブ閉鎖・リロード・休止・クラッシュでは保護を自動解除しません。復帰するタブや失われたレスポンスを期限だけで推測して削除しないためです。
- `MAX_UPLOAD_COUNT` / `MAX_JOB_COUNT` は、ディスク上の既存ディレクトリと未保存の予約を含む上限です。保護対象だけで上限に達する場合、新規バッチ・ジョブを **HTTP 507** と説明付きで拒否します。設定引下げ等ですでに上限を超えていても必要な素材は消さず、追加保存を停止します。自動サムネイルはジョブ枠がない場合だけ省略します。
- 進行中ジョブは、入力アップロード・入力ジョブ成果・自身の作業ディレクトリを完了/失敗まで保護します。ジョブ結果をタブへ返す前にそのタブの保護に含め、ポーリング・ダウンロード・Undo後の再利用まで維持します。終了後のメタデータ書込みが削除済みディレクトリを再作成しないよう、書込み完了後に保護を解除します。
- 旧版の既存素材、セッションIDのないAPI呼び出し、途中で失われたセッション等は「不要」と判定できないため保持します。その場合も保存上限で追加を拒否し、無制限には増やしません。不要なタブではブラウザを閉じる前に「編集終了・素材解放」を利用してください。すでに閉じたタブの参照や旧素材を整理するには、運用者が該当の編集状態とジョブが不要であることを確認する必要があります。端末のアップロード元ファイルは操作しません。
- JSON保護情報が不正・保存不能、またはプロセス間ロック `retention.json.lock` が残っている場合は、削除と新規保存を **HTTP 503** で停止します。ロックに自動期限はなく、プロセスが途中停止した場合も安全側に残します。復旧は運用者が全プロセスの停止と保護情報を確認して行います。このMVPは単一Next.jsプロセス・同一ローカルストレージでの利用を前提とし、共有ホスト間での参照管理は対象外です。
- `/api/storage/prune` の `keepIds` はその呼び出し中の追加保護に使い、他タブの保護を置換しません。セッション登録・追加保護・明示的解放には `/api/storage/session` を使います。Blob上の原本削除は行わず、この件数整理はローカル保存領域が対象です。BlobのアップロードIDは解放後も件数に含め、失敗したアップロードの予約も原本が残っていないと確認できるまでは返却しません。枠を使い切った場合は追加を拒否します（運用者による原本削除・台帳確認が必要です）。
- 試験用に `MOVIE_EDITOR_STORAGE_ROOT` で保存先を変更できます。通常は `storage/`、Vitestはテストファイルごとに隔離した一時ディレクトリを使用します。ブラウザ試験でも合成素材と専用の一時保存先を利用してください。
- 結合クリップの右端短縮は、残る範囲のパートと素材内の開始位置を保持します。延長は現在の末尾パートのみを伸ばします。動画はその素材の末尾で停止し、画像は指定時間まで表示します。短縮で取り除いたパートを戻すには Undo を使用します。
- 選択クリップ書き出しは全パートを順番に出力します。同一素材の非連続区間、異なる動画、画像の混在に対応します。既存の単一動画書き出しと同じくタイムラインの位置・変形は適用せず、画像・複数パートは先頭素材を基準にした共通キャンバスで配置モードを適用します（既定は引き伸ばし、明示的に縦横比保持も選択可）。混在パートは30fps・共通解像度・48kHzステレオへ揃え、画像や無音動画の区間は無音にします。素材が欠ける場合や動画の参照範囲が末尾を超える場合はエラーとし、部分出力を成功扱いしません。

実ffmpegの回帰テスト（通常テストでは実行しません）:

```bash
RUN_FFMPEG_TESTS=1 FFMPEG_PATH=/usr/bin/ffmpeg FFPROBE_PATH=/usr/bin/ffprobe npm test -- lib/exportComposition.regression.test.ts lib/exportComposition.timing.test.ts
```

合成書き出しでは素材映像のPTSをタイムライン配置時刻へ揃え、表示区間は開始時刻を含み終了時刻を含みません。画面外へ移動・拡大したクリップはプレビューと同様にクロップします（中心座標は有限数、倍率は0.2〜3）。音声の配置遅延はAPIで許可する24時間までのコンポジションに対応します。

`exportComposition.timing.test.ts` は隔離した320×320の色・音切替素材を使い、0秒/途中開始、隣接境界、複数トラック、結合クリップ、負座標、99.999/100/100.001/101/180.25秒配置の出力長・フレーム内容・音声を実ffmpeg/ffprobeで検証します。24時間上限は全長動画を生成せず単体テストで検証します。

## 保存・読み込みの実ブラウザ検証

ブラウザ回帰は本番ビルド、Playwright Chromium、実 ffmpeg/ffprobe を使います。各スイートの既定ポート（`scripts/verify-*.mjs` の `verification` 呼び出しを参照）を空けて実行してください。`BROWSER_PORT` で上書きでき、各スイートは順次実行されます。合成素材と独立した一時ストレージを使い、既存の `storage/` には触れません。

```bash
npm ci
npx playwright install --with-deps chromium
npm run build
npm run test:typecheck
npm run test:browser
```

`FFMPEG_PATH` / `FFPROBE_PATH` でバイナリを指定できます（既定はシステム PATH）。既存 Chromium を明示する場合は `CHROMIUM_PATH` を指定します。履歴回帰は選択・シーク・再生後の Redo と新規編集後の履歴破棄を検査します。保存復元回帰はサーバーを再起動し、保存→編集終了→再起動→読み込み→書き出し、結合・速度復元、JSON、欠損素材の再指定、複数タブ、実 PNG/JPEG を検査します。すべての書き出しを ffprobe と全体デコードで確認し、動画出力の映像・音声も検査します。JSON・MP4・スクリーンショット・ログは `test-results/` に残ります（`BROWSER_RESULTS_DIR` で変更可）。

実 ffmpeg 回帰を含む全 Vitest テストは `RUN_FFMPEG_TESTS=1 npm test`、通常の単体テストは `npm test` で実行できます。

### クリップの縦横比を保持する

クリップを選び、タイムラインの「配置」から「縦横比を保持（全体を表示）」を選択すると、素材全体を現在の配置枠へ中央揃えで収めます。余白と画像の透過部分には下のトラック、または背景が見えます。位置・拡大率・時間は変わりません。「画面にフィット」は従来どおり配置枠を画面全体に広げる操作です。複数選択はまとめて1回の Undo で戻せます。異なる配置モードのクリップは、モードを揃えてから結合してください。

既定は従来の引き伸ばしです。旧プロジェクトもそのまま読み込めます。縦横比保持を含む新しい保存版・JSON は v2 となり、旧アプリでは開けません。全て引き伸ばしに戻した後の新しい保存版は v1 です。過去の保存版は変更しません。未知の保存バージョンは拒否します。

全体書き出しは配置を反映します。「選択クリップ DL」は従来の素材切り出しで、タイムライン位置や配置枠を適用しません。単一動画は素材サイズのまま、画像・複数素材は先頭素材の比率の画面内で配置モードを適用します。

縦横比保持は正方形ピクセル、認識済みの90度単位の回転、静止画像を対象とします。非正方形ピクセル、不明な回転・EXIF Orientation、アニメーション画像などは適用時と書き出し時に検査し、対応外ならエラーを表示します。保存済みの対応外クリップは自動で引き伸ばしへ変えず、該当レイヤーを描画しません。読込中の素材も引き伸ばしへ代替表示しません。

縦横比保持を含む書き出しは、クリップごとの色映像と可逆圧縮の透過情報を一時作成するため、従来より書込量やデコーダー負荷が増えます。短い1080pの代表例で確認していますが、高速化は保証しません。4K・長尺・最大クリップ／パート数・高密度映像・最大拡大率・並列ジョブの性能や必要容量は未検証です。既存の入力上限は性能保証ではありません。
