# movie_editor（ローカル MVP）

ブラウザ上で動くマルチトラック動画エディタです。素材のアップロード、タイムライン編集（分割・結合・Undo/Redo）、Canvas 合成プレビュー、ffmpeg による書き出しまでを単一の Next.js プロセスで行います。

[`scripts/restore_speed.sh`](scripts/restore_speed.sh) と同等の ffmpeg フィルタで「倍速っぽい動画」を元の速度・音程へ戻す機能も含みます。

## 主な機能

### 素材・タイムライン

- **素材ライブラリ** — 動画（mp4/mkv/avi/mov/flv/wmv）と画像（png/jpg/jpeg/webp/gif）を複数同時アップロード
- **マルチトラックタイムライン** — 素材をドラッグして配置、トラック追加（+）・空トラック削除、移動・端ドラッグで長さ変更
- **クリップ編集** — 分割・結合（同一トラック・複数選択）・削除・複製
- **重なり回避** — クリップ移動時、同一トラック上の重なりを自動で前後にスナップ
- **フィルムストリップ** — 動画クリップにサムネイル帯を表示（アップロード後に非同期生成）
- **タイムラインズーム** — 0.25×〜4×

### プレビュー・合成

- **Canvas プレビュー** — 複数トラックの映像を重ね合わせ（下位トラックが背面）
- **変形** — 選択クリップの移動・四隅ハンドルでスケール、ダブルクリックまたは ⛶ で画面フィット
- **再生** — 再生/一時停止、1フレーム送り、先頭/末尾ジャンプ、全画面プレビュー
- **タイトル** — 日本語本文・手動改行を再編集できるタイトル、同じ透明PNGによるプレビューと全体出力
- **音声** — クリップ音量0〜100%と0%消音をプレビュー・全体出力へ適用（素材DLは元音声、音声の選択規則は従来どおり）
- **レイアウト** — プレビューとタイムラインの境界をドラッグで高さ調整（`localStorage` に保存）

### ジョブ・書き出し

- **速度復元** — 選択した動画クリップに `scripts/restore_speed.sh` 相当の ffmpeg 処理を適用
- **選択クリップ書き出し** — タイムライン上の区間を mp4 でダウンロード
- **全体書き出し** — 「合成解像度」で設定したサイズのタイムライン合成を mp4 でエクスポート
- **合成解像度** — 1920×1080（16:9）・1080×1920（9:16）・1080×1080（1:1）のプリセット、最初のクリップ配置時の自動設定、選択クリップの「素材に合わせる」に対応
- **Undo / Redo** — 編集操作の取り消し（Ctrl+Z / Shift+Ctrl+Z）

### プロジェクト保存・読み込み（ローカルストレージ）

- 「新しい保存版を保存」で、素材一覧・トラック・配置・切り出し／結合 parts・変形・合成サイズ／時間・名前をサーバーへ明示保存します。空プロジェクト・素材だけの状態も保存できます。
- 保存は毎回独立した版になります。保存一覧から読み込み、同じ内容の JSON ダウンロード、保存版の明示削除ができます。ダウンロード開始はサーバー保存の成否・ダウンロード完了と区別して表示します。
- 保存版が参照する素材は「編集終了・素材解放」後も残ります。保存版を削除するとその版の保護だけを解除します。他版・他タブ・実行中ジョブの参照は維持します。保存版は最大50件で、上限では自動削除せずエラーにします。
- JSON は `format: "movie-editor-project"` の専用 DTO です。音声フェードを含む保存は version 5、タイトルを含む保存は version 4、タイトルなしで100%以外の音量を含む保存は version 3、音量が既定のままで縦横比保持を含む保存は version 2、その他は version 1 です。v1/v2/v3/v4/v5を読み込み、未知のversionと旧versionへの音量・フェードfield持込みは拒否します。素材本体、URL、絶対パス、Undo/Redo、再生位置、選択、ジョブ実行状態は含みません。JSON は最大2 MiB、素材50件、トラック20件、クリップ100件、各クリップの parts 50件、合成時間24時間までです。
- 読み込みは形式・参照・数値範囲・素材の実ファイル SHA-256／サイズ・実動画区間をすべて検証し、タブの素材保護を永続化してから一括採用します。停止・位置0・選択なし・新しい履歴で開始します。未保存変更には保存／破棄／キャンセルを確認し、失敗・欠損・キャンセルでは既存の編集と履歴を維持します。
- 欠損素材は同じバイト列のファイルを再指定してください。同名だけでは対応付けません。速度復元済み素材には元動画ではなく復元後の成果物が必要です。素材の論理IDは再指定後も維持し、保存先IDと区別します。
- 素材保護と保存版 manifest は `storage/retention.json` 内に同居し、同じ排他処理と原子的なファイル置換で確定します。応答消失時の再試行も同じ保存版IDで処理し、旧保存版の上書き・保護解除を行いません。削除済み保存版IDは素材参照を持たない削除記録として残し、遅延した保存再試行による復活を拒否します。ジョブ成果物を参照する場合は、再起動後の解決に必要なジョブ情報も原子的に永続化してから成功を返します。単一 Next.js プロセス専用です。Blob を使用する構成では保存・読み込みを明示拒否します。
- バックアップ・移動時には JSON と対応する素材ストレージを別途保管してください。素材を含まない JSON だけでは別環境での再開を保証しません。

## 使い方（概要）

1. ブラウザで `http://127.0.0.1:3000` を開く
2. 左の素材パネルから動画・画像をアップロード
3. 素材カードをタイムラインのトラックへドラッグするか、カードの「Tnの再生位置へ追加」でクリップを配置
4. 中央の Canvas プレビューで位置・サイズを調整、下部ツールバーで分割・結合・書き出しなどを実行

追加ボタンは Tab で選び、Enter／Space でも操作できます。追加先は選択中クリップのトラック（複数選択時は最初に選択した有効なクリップ）で、選択がなければ最上段のトラックです。ボタンの T 番号で確認できます。トラックがなければ「＋」で追加してください。

複数クリップは Ctrl/Cmd+クリックで選択し、選択済みクリップを修飾キーなしでドラッグすると、間隔を保ってまとめて横へ移動できます。元トラックは変わらず、選択外クリップと重なる移動は全体を確定しません。1回の Undo で全員を戻せます。掴んだクリップの始端・終端は再生位置へ吸着し、Altで一時解除できます。Ctrl/Cmdを押したまま開始する移動と単独移動・右端のサイズ変更は従来どおりです。

2個以上を選択して「再生位置へ」を押すと、選択群の最も早い先頭を、指定した再生位置へまとめて移動します。選択順によらず間隔・トラック・素材の参照と音声フェードの位置関係を維持し、1回の Undo で戻せます。必要な右端だけ合成時間を延長し、短縮はしません。重なりや無効な移動・移動量ゼロでは履歴と保留中の Redo を変えず、理由をボタンの説明に表示します。再生状態は変えませんが、操作の採用前に再生位置が進むと移動を取り消すため、再生を止めて位置を指定してから操作してください。ドラッグ操作中は使えません。

追加する区間が既存クリップと重なる場合は空き位置へ調整し、素材パネルに実際の追加先と秒数を表示します。他のクリップは動かしません。追加は初回の合成解像度設定も含めて1回の Undo で戻せます。

空トラックは行見出しの「削除」から削除できます。クリップがあるトラックと最後の1トラックは削除できず、処理中も操作できません。削除できない理由はボタンの説明で確認できます。残るトラックの重なり順と同順位の関係を保って T 番号を詰め直し、1回の Undo で元のトラックと番号へ戻せます。素材一覧の素材や既存クリップは削除しません。

### 合成解像度の設定

- 空プロジェクトの初期値は 1920×1080 です。空のタイムラインへ最初の動画・画像クリップを配置すると、素材の寸法が取得できていれば合成解像度を自動設定します。全クリップを削除してから配置し直した場合も同じです。アップロードだけでは変更せず、すでにクリップがあるタイムラインへの追加でも変更しません。
- プレビュー上部の「合成解像度」から 16:9・9:16・1:1 のプリセットを選べます。空のタイムラインで選んだ設定は初回配置時の自動設定で変わるため、プリセットで書き出す場合は配置後に選んでください。
- クリップを選んで「素材に合わせる」を押すと、その素材から合成解像度を再設定します。複数選択時は選択一覧の先頭クリップ、結合クリップでは先頭パートの素材を基準にします。
- 素材からの自動／手動設定は元のピクセル数をそのまま採用するのではなく、長辺を1920ピクセルに換算し、各辺を320〜4096ピクセルの範囲の偶数へ調整します。たとえば3840×2160は1920×1080、正方形は1920×1920になります。プリセット以外のサイズは「カスタム」と表示されますが、幅・高さの任意入力はありません。
- 新しくアップロードした動画は、認識できる表示行列の90度単位の回転を素材寸法へ反映し、初回配置時の自動合成解像度に使います。既存の保存版の素材寸法・合成解像度・クリップ配置は変更しません。任意角度、SAR、画像のEXIF回転、旧APIの寸法や既存素材の「素材に合わせる」の再解釈は対象外です。
- 合成解像度はプレビューの縦横比と全体書き出しに反映されます。既定では各クリップを変形領域へ引き伸ばして描画します。明示的に「縦横比を保持（全体を表示）」を選ぶと、素材全体を枠内中央に収め、余白は透明になります。詳しくは「クリップの縦横比を保持する」を参照してください。選択クリップ書き出しは別の処理で、詳細は末尾の仕様を参照してください。

設定を手動確認する場合は、合成した横長・縦長・正方形の動画／画像を使い、空のタイムラインへの初回配置、2本目の追加、プリセット切替、「素材に合わせる」を順に確認します。全体書き出し後は `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of json output.mp4` で、出力寸法が画面の合成解像度と一致することを確認してください。既存データを使わず、専用の一時ストレージで検証してください。

### 再生位置で先頭・末尾を短縮する

クリップを1つ選び、残したい境界へ再生位置を合わせて、タイムラインの「先頭を再生位置まで短縮」または「末尾を再生位置まで短縮」を押します。動画・画像・結合クリップ・タイトルに使え、それぞれ1回のUndoで戻せます。末尾短縮は先頭と素材の開始位置、合成時間を維持します。後続クリップは動かさず、短縮後の空白を自動で詰めません。0.05秒未満になる位置や範囲外では、ボタンの理由を確認してください。

音声フェードは元の位置を保ち、新しい末尾へ移動しません。短縮後の末尾でフェードアウトさせたい場合は、短縮後にフェードを再適用してください。元素材や過去の保存版は変更しません。

## CI

GitHub Actions（`.github/workflows/ci.yml`）: `npm ci` → ffmpeg・Chromium 導入 → lint → 実 ffmpeg を含む test → build → 型チェック → browser → audit。

CI は ffmpeg と Playwright Chromium をインストールし、実 ffmpeg 回帰、production build、型チェック、履歴・保存復元のブラウザ回帰を必須実行します。ブラウザの証拠は CI artifact として7日間保存します。

## 素材保護と結合クリップの仕様

- タブごとに素材保護セッションを作り、`storage/retention.json` に保護IDを原子的に記録します。素材一覧・タイムライン・Undo/Redoの全履歴・復元ジョブ成果を含み、保護情報は追加方式です。アップロードは同一バッチの全IDを保存前にまとめて予約し、別タブの参照はそのタブが解放するまで残します。
- **「編集終了・素材解放」** で、このタブの編集内容・素材一覧・履歴を破棄することを確認すると参照を解放します。他タブも実行中ジョブも参照しなくなった管理対象だけを自動整理します。通常のタブ閉鎖・リロード・休止・クラッシュでは保護を自動解除しません。復帰するタブや失われたレスポンスを期限だけで推測して削除しないためです。
- `MAX_UPLOAD_COUNT` / `MAX_JOB_COUNT` は、ディスク上の既存ディレクトリと未保存の予約を含む上限です。保護対象だけで上限に達する場合、新規バッチ・ジョブを **HTTP 507** と説明付きで拒否します。設定引下げ等ですでに上限を超えていても必要な素材は消さず、追加保存を停止します。自動サムネイルはジョブ枠がない場合だけ省略します。
- 進行中ジョブは、入力アップロード・入力ジョブ成果・自身の作業ディレクトリを完了/失敗まで保護します。ジョブ結果をタブへ返す前にそのタブの保護に含め、ポーリング・ダウンロード・Undo後の再利用まで維持します。終了後のメタデータ書込みが削除済みディレクトリを再作成しないよう、書込み完了後に保護を解除します。
- 旧版の既存素材、セッションIDのないAPI呼び出し、途中で失われたセッション等は「不要」と判定できないため保持します。その場合も保存上限で追加を拒否し、無制限には増やしません。不要なタブではブラウザを閉じる前に「編集終了・素材解放」を利用してください。すでに閉じたタブの参照や旧素材を整理するには、運用者が該当の編集状態とジョブが不要であることを確認する必要があります。端末のアップロード元ファイルは操作しません。
- JSON保護情報が不正・保存不能、またはプロセス間ロック `retention.json.lock` が残っている場合は、削除と新規保存を **HTTP 503** で停止します。ロックに自動期限はなく、プロセスが途中停止した場合も安全側に残します。復旧は運用者が全プロセスの停止と保護情報を確認して行います。このMVPは単一Next.jsプロセス・同一ローカルストレージでの利用を前提とし、共有ホスト間での参照管理は対象外です。
- `/api/storage/prune` の `keepIds` はその呼び出し中の追加保護に使い、他タブの保護を置換しません。セッション登録・追加保護・明示的解放には `/api/storage/session` を使います。Blob上の原本削除は行わず、この件数整理はローカル保存領域が対象です。BlobのアップロードIDは解放後も件数に含め、失敗したアップロードの予約も原本が残っていないと確認できるまでは返却しません。枠を使い切った場合は追加を拒否します（運用者による原本削除・台帳確認が必要です）。
- 試験用に `MOVIE_EDITOR_STORAGE_ROOT` で保存先を変更できます。通常は `storage/`、Vitestはテストファイルごとに隔離した一時ディレクトリを使用します。ブラウザ試験でも合成素材と専用の一時保存先を利用してください。
- 結合クリップの右端短縮は、残る範囲のパートと素材内の開始位置を保持します。延長は現在の末尾パートのみを伸ばします。動画はその素材の末尾で停止し、画像は指定時間まで表示します。短縮で取り除いたパートを戻すには Undo を使用します。
- 選択クリップ書き出しは全パートを順番に出力します。同一素材の非連続区間、異なる動画、画像の混在に対応します。既存の単一動画書き出しと同じくタイムラインの位置・変形は適用せず、画像・複数パートは先頭素材を基準にした共通キャンバスで配置モードを適用します（既定は引き伸ばし、明示的に縦横比保持も選択可）。混在パートは30fps・共通解像度・48kHzステレオへ揃え、画像や無音動画の区間は無音にします。素材が欠ける場合や動画の参照範囲が末尾を超える場合はエラーとし、部分出力を成功扱いしません。

実ffmpegの回帰テスト（通常テストでは実行しません）:

```bash
RUN_FFMPEG_TESTS=1 FFMPEG_PATH=/usr/bin/ffmpeg FFPROBE_PATH=/usr/bin/ffprobe npm test -- lib/exportComposition.regression.test.ts lib/exportComposition.timing.test.ts
```

合成書き出しでは素材映像のPTSをタイムライン配置時刻へ揃え、表示区間は開始時刻を含み終了時刻を含みません。画面外へ移動・拡大したクリップはプレビューと同様にクロップします（中心座標は有限数、倍率は0.2〜3）。音声の配置遅延はAPIで許可する24時間までのコンポジションに対応します。

`exportComposition.timing.test.ts` は隔離した320×320の色・音切替素材を使い、0秒/途中開始、隣接境界、複数トラック、結合クリップ、負座標、99.999/100/100.001/101/180.25秒配置の出力長・フレーム内容・音声を実ffmpeg/ffprobeで検証します。24時間上限は全長動画を生成せず単体テストで検証します。

## 保存・読み込みの実ブラウザ検証

ブラウザ回帰は本番ビルド、Playwright Chromium、実 ffmpeg/ffprobe を使います。各スイートの既定ポート（`scripts/verify-*.mjs` の `verification` 呼び出しを参照）を空けて実行してください。`BROWSER_PORT` で上書きでき、各スイートは順次実行されます。合成素材と独立した一時ストレージを使い、既存の `storage/` には触れません。

```bash
npm ci
npx playwright install --with-deps chromium
npm run build
npm run test:typecheck
npm run test:browser
```

`FFMPEG_PATH` / `FFPROBE_PATH` でバイナリを指定できます（既定はシステム PATH）。既存 Chromium を明示する場合は `CHROMIUM_PATH` を指定します。履歴回帰は選択・シーク・再生後の Redo と新規編集後の履歴破棄を検査します。保存復元回帰はサーバーを再起動し、保存→編集終了→再起動→読み込み→書き出し、結合・速度復元、JSON、欠損素材の再指定、複数タブ、実 PNG/JPEG を検査します。すべての書き出しを ffprobe と全体デコードで確認し、動画出力の映像・音声も検査します。JSON・MP4・スクリーンショット・ログは `test-results/` に残ります（`BROWSER_RESULTS_DIR` で変更可）。

実 ffmpeg 回帰を含む全 Vitest テストは `RUN_FFMPEG_TESTS=1 npm test`、通常の単体テストは `npm test` で実行できます。

### クリップの縦横比を保持する

クリップを選び、タイムラインの「配置」から「縦横比を保持（全体を表示）」を選択すると、素材全体を現在の配置枠へ中央揃えで収めます。余白と画像の透過部分には下のトラック、または背景が見えます。位置・拡大率・時間は変わりません。「画面にフィット」は従来どおり配置枠を画面全体に広げる操作です。複数選択はまとめて1回の Undo で戻せます。異なる配置モードのクリップは、モードを揃えてから結合してください。

既定は従来の引き伸ばしです。旧プロジェクトもそのまま読み込めます。タイトルを含まない場合、音量が全て100%で縦横比保持を含む新しい保存版・JSONはv2、全て引き伸ばしならv1です。100%以外の音量を含む保存はv3で、それに未対応の旧アプリでは開けません。過去の保存版は変更しません。未知の保存バージョンは拒否します。

全体書き出しは配置を反映します。「選択クリップ DL」は従来の素材切り出しで、タイムライン位置や配置枠を適用しません。単一動画は素材サイズのまま、画像・複数素材は先頭素材の比率の画面内で配置モードを適用します。

縦横比保持は正方形ピクセル、認識済みの90度単位の回転、静止画像を対象とします。非正方形ピクセル、不明な回転・EXIF Orientation、アニメーション画像などは適用時と書き出し時に検査し、対応外ならエラーを表示します。保存済みの対応外クリップは自動で引き伸ばしへ変えず、該当レイヤーを描画しません。読込中の素材も引き伸ばしへ代替表示しません。

contain全体書き出しの独立音声抽出では、映像が正原点・音声とformatが原点0、映像／音声各1stream、要求区間の末尾まで音声durationがある場合に限り、成功した旧WAVが実測で明確に短いときだけ別WAVへ最大1回再抽出します。先頭以外の区間も、初回抽出と同じ最大小数9桁のsource開始引数を使い、入力を復号してから音声を切り出します。正の開始位置では開始秒と長さをそれぞれµs単位で安全側へ切り上げて範囲を判定するため、音声末尾の最大2µs弱にかかる区間は対象外になる場合があります。健康な旧WAV、原点0、不明な診断、範囲外、失敗・時間超過では旧出力を維持し、元素材と旧WAVは書き換えません。

補助probeは5秒、再抽出は30秒、TERM猶予1秒、stdout/stderr合計1MiBの既存予算内です。先頭から復号するためsource開始位置が遅いほど処理費用が増え、長尺／4Kの性能は保証しません。固定合成素材でPCMのsource区間・pulse位置・映像境界を確認していますが、sample数回復だけで全素材の先頭音を保証しません。

異原点AVの選択DL／stretch（単一・結合part）も、映像正原点・audio／format原点0・各1stream・両streamの要求範囲被覆・映像のr_frame_rateが30/1で平均rateが15〜30fpsと確認した場合に限定修復します。まず従来の抽出を行い、映像／音声の欠落、1フレームを超える開始遅延または短縮が実測された場合だけ別候補を生成します。映像は30fpsの直前フレーム保持、音声は全復号・48kHz化したPCMからsource区間を切り出し、各streamの原点を出力0秒へ揃えます。補助予算は上記と同じで、候補の両stream・長さ・入力identityを再検証してから原子的に採用します。正常な旧出力bytes、不明な診断、非対象metadata、失敗・時間超過は維持します。選択DLで映像の不在が明確に確認でき、修復できない場合は成功扱いせずエラーになります。負PTS・一般VFR・その他の原点組合せや全形式の統一は未完了（#72）です。

古い同梱probeが正の映像起点をdurationへ含める場合に備え、修復前には全映像packetのPTS／durationも確認します。30Hz上で各packetが1または2tick続き、隙間・重複なく連続し、実測平均rateもmetadataと一致する場合だけ対象です。VFRの実末尾はpacket数でなく最終PTS＋durationから有理数で計算します。この追加診断も各5秒／出力1MiB以内で、長尺・不連続・格子外・3tick以上・不明なpacket情報は修復対象外です。時刻端数の被覆判定は有理数とµs単位の安全側切上げを使い、末尾近傍の最大2µs弱を保守的に除外する場合があります。

修復候補の映像時計は30Hzを厳密に表せる1/1920000000秒へ変換してからsource開始を差し引きます。入力tickや1µsへの丸めで境界直前のフレームを早送りしないためで、元の正常出力は変更しません。検証は0.5秒および1/30秒境界の±1µsまでで、ns境界や一般VFRの一致は保証しません。既存containの入力tick未満の境界精度はこの変更の対象外です。[再現マトリクスと限定範囲](docs/av-clock-matrix.md)を参照してください。

縦横比保持を含む書き出しは、クリップごとの色映像と可逆圧縮の透過情報を一時作成するため、従来より書込量やデコーダー負荷が増えます。短い1080pの代表例で確認していますが、高速化は保証しません。4K・長尺・最大クリップ／パート数・高密度映像・最大拡大率・並列ジョブの性能や必要容量は未検証です。既存の入力上限は性能保証ではありません。


### クリップ音量・0%消音

動画パートを含むクリップを選び、「音量 %」へ整数0〜100を入力して「音量を適用」またはEnterで確定します。「消音（0%）」は音量を0へ設定します。別の音量へ戻すときは任意の%を再指定します。入力途中は編集履歴に入らず、Escapeで取消、1回の適用を1回のUndoで戻せます。複数選択は動画を含むクリップだけへ一括適用し、純画像の除外件数を表示します。異なる音量の動画クリップは、音量を揃えてから結合してください。

音量はプレビューと全体書き出しに適用します。選択素材のダウンロードは単一動画・複数パートとも元音声のままです。音量は素材bytesや速度・ソース時刻を変更しません。タイトルを含まない場合、非既定音量はv3保存へ含め、全て100%へ戻した後の新しい保存は従来のv1/v2へ戻ります。過去の保存版は変更しません。

音声選択は従来どおりです。プレビューは各時刻の既存の動画クリップ、全体出力は既存の固定音声トラックを選び、その後に音量を適用します。0%でも下層の音声へ切り替えません。たとえば上位トラックに空き時間がある場合、プレビューでは下層動画の音声が選ばれ、固定上位トラックを使う全体出力では無音になる既存の差があります。音量機能はこの選択規則の統一や一般的なAV時計の補正、独立muteの音量記憶を追加しません。


### クリップの音声フェード

動画パートを含むクリップを1つ選び、素材パネルの「音声フェード」でイン・アウトの秒数を指定し「フェードを適用」またはEnterで確定します。非負の秒数を小数3桁まで入力でき、合計は現在のクリップの長さ以内にします。「フェードを解除」は元の音量へ戻します。音量設定には重ねて適用し、素材そのものの音声や速度は変えません。入力中は履歴に入らず、Escapeで取消、適用・解除はそれぞれ1回のUndoで戻せます。

分割や先頭トリム後も元のフェードの位置を引き継ぎます。右端を延ばしても元のアウト位置は移動せず、その後は無音です。新しい長さで設定し直す場合は再適用してください。同じフェードの連続する分割片は結合できます。別の設定や位置が混在する場合は各クリップのフェードを解除してから結合します。分割で画像のみになった片も、引き継いだフェードは解除できます。速度復元で使う素材を参照する別クリップも含め、フェードが残る場合は先に解除してください。

プレビューと全体書き出しへ適用し、選択クリップDLは元音声を保ちます。プレビューの既存音声選択と全体出力の固定音声トラック選択の差は維持します。プレビューは専用の音声プレイヤーとWeb Audioを1組だけ使い、再生ボタンから開始します。ブラウザの制約や音声処理の停止時はフェードを無視して再生せず、エラーを表示します。「音声フェードを再試行」で専用プレイヤーを作り直した後、再生してください。フェードを解除したクリップは従来の音声経路を利用できます。細かなサンプル境界や一般的なAV同期の補正を保証する機能ではありません。

フェードを含む新しい保存・JSONはv5です。v1〜v4も読み込み、過去の保存版は変更しません。すべてのフェードを解除した新しい保存は、タイトル・音量・配置に応じて最小のv1〜v4へ戻ります。v5未対応の旧アプリでは開けません。


### 再編集できる日本語タイトル

素材パネルの「タイトル追加」で再生位置へ5秒のタイトルを置きます。前面トラックが埋まっている場合は新しい前面トラックを一緒に作り、追加全体を1回のUndoで戻せます。タイトルを1つ選び「タイトル本文」を変更して「本文を適用」で確定します。Enterは改行、変換中のEnterは文字入力として扱い、Escapeは未適用の入力を取り消します。本文確認に失敗した場合は元の本文と履歴を保持します。

日本語のかな・漢字、半角カナの濁点、基底付き結合文字、手動改行と通常の記号を、同梱の固定日本語fontで描画します。半角バックスラッシュと波括弧、異体字指定・ZWJ・絵文字修飾等の未対応文字列、未収録glyphはU+番号付きで拒否し、別文字へ置換しません。横書き・白字/黒縁・固定fontの初版です。自動字幕、縦書き、font選択・アップロード、文字アニメーションは含みません。

長い本文は構図内に収まるよう字号を縮めます。改行すると大きく表示できます。十分な字号で収まらない場合はエラーを表示します。タイトルの初期scale1は構図全体を使い、既存素材の半画面scale1と区別します。位置・拡大率・長さ・複製・分割・一括横移動を調整でき、プレビューと全体出力は同じ透明PNGを使います。タイトルは無音で、既存素材の音声選択と時刻の規則を変更しません。タイトルを含む選択では素材DL・速度復元・結合・音量変更を利用できません。

フェードがなくタイトルを含む保存・JSONはv4です。本文/font revisionが正本で、派生PNGやcachepathを保存しません。画像cacheが消えても読み込み/明示再試行で再生成できます。タイトルを全て削除した新しい保存は、音量・配置に応じ従来の最小v1/v2/v3へ戻ります。旧版の保存、素材再リンク、sourceJob参照は保持します。v4未対応の旧アプリでは開けません。

タイトル描画には同梱Noto Sans CJK JP（無改変TTC、約18.6MiB、OFL1.1）とbundled static ffmpegを固定して使用し、export用FFMPEG_PATHやhost fontへ代替しません。fontの出所・Adobe/Google notice・OFL全文はvendor/fonts/noto-sans-cjk/にあります。現在の対応は必要なlibassを持つLinux static実体です。対応外環境ではタイトルの明示エラーを返し、従来の素材処理を使い続けられます。rendererの変更後に以前の版と任意字形が完全一致する保証はありません。

派生データはstorage/title-cache/だけへ保存します。PNG+metricsは合計128MiB/128entry、1entry32MiB、生成は1件・待機16keyまでです。同keyは共有し、過負荷は429で返します。previewはactive titleだけを逐次取得し、原寸PNGの表示用decodeを縮小して常駐bitmapを64MiB以内へ抑えます（一時decodeやffmpeg作業memoryは別です）。exportは自身のjob一時領域へPNGをcopyしてから使用し、cache回収と競合しません。

起動時はboot/PID/process開始時刻で生存ownerを識別し、死んだownerの専用派生データだけを回収します。同じ保存先の別の生存ownerや所有不明データは勝手に削除せずエラーにします。PNG/metricsの消失・破損は成功扱いせず、lease終了後の明示再試行で再生成します。生存serverのcanonical binary/font/owner全体を外部削除した場合は安全に生成を停止します。元媒体・保存版を操作せず、serverを停止してから専用cacheを確認してください。最大4K/長文/100clip等での速度・最大memoryや空き容量は保証しません。

編集を終えたら再生を停止し、プレビューの「動画の長さを内容に合わせる」で最後のクリップまで動画長を短縮できます。すべてのトラック・タイトルが対象で、先頭・途中の空白と各クリップは維持します。末尾に意図した余韻があっても削られますが、Undoで動画長と再生位置を戻せます。後の追加・複製・分割などの編集で動画長が再び延びる場合は、書き出し前に再適用してください。

Ctrl/Cmd+Aで全トラックの全クリップを選択できます。先に選んだクリップの順序を保ち、未選択の映像・画像・タイトルも追加します。入力欄では文字の全選択が優先されます。全体を移動する際は、全選択してから既存の「再生位置へ」を使えます。全選択自体は編集履歴を追加せず、Redoも維持します。

プレビュー映像のsource時刻は素材の先頭からの秒数です。HTML videoの時計が正の時刻から始まる素材では、映像要素ごとの初回0秒シーク完了時にブラウザが実際に採用した先頭時刻を測り、その後のsource時刻へ加えます。メタデータ読込直後の仮の時刻や、常に0になり得るseekable/bufferedの先頭値からは推測しません。EOFではその時点の実durationを上限にします。正原点の完了シークが要求より1〜2µs手前へ落ちた場合だけ、最大1回の微小補正を行います。サブµs境界の厳密一致を保証するものではありません。保存source値・Undo履歴・書き出し処理は変更しません。

無音の合成MP4（原点0、約0.01/0.033/0.2/2秒）とVP9 Matroska（約0.033秒）について、固定した色切替をプレビュー・選択書き出し・stretch/contain全体書き出しで検証します。映像正原点・audio／format原点0・各1streamと厳密なdurationを実ファイルから確認できる場合、HTML映像時計の較正値が0ならサーバー確認済みの映像起点を用います。既に正の起点が測定された要素へは二重加算しません。音声用のnative／fade再生時計と保存値は変更しません。固定AV（映像+2秒／音声0秒）の先頭・非zero sourceInで映像境界と音声pulseを検証します。その他の原点組合せ、負原点、一般VFRや全ブラウザへの一般化は未検証です。
